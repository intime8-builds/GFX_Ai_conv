# GFX Ai Conv

Локальное Windows-приложение для подготовки AI-конформа по shot:

```text
plate
→ conservative temporal denoise
→ BlackOutside
→ undistort из последнего 3DE/Nuke track в исходном разрешении
→ Reformat в выбранное выходное разрешение
→ ACES OCIO Output Transform в Rec.709
→ MOV ProRes 4444
→ двухпроходный Topview H.264 до 64 МБ
→ QC JSON
```

Стабильный старый конвертер сохранён в Git tag `v0.1.11`. Новая концепция
начинается с версии `v0.2.0-alpha.1`.

## Требования

- Windows x64.
- Nuke 15–17 с `python.exe`, `PyOpenColorIO` и ACES OCIO config.
- Для обработки не запускается интерфейс Nuke и не используется Nuke license.
  Приложение берёт из локальной установки только Python, PyOpenColorIO и
  color config.
- FFmpeg, NumPy и OpenCV поставляются вместе с приложением.

Undistort реализован внутри приложения по открытой математике 3DE. Сейчас
поддерживается нода:

```text
LD_3DE4_Radial_Standard_Degree_4
```

Работают статические коэффициенты и экспортированные Nuke curves. Если в `.nk`
другая модель линзы, приложение завершит анализ с явной ошибкой.

## Рабочий Процесс

1. Нажмите `Файл` для видео, изображения или одного EXR-кадра. Для выбора
   каталога целиком нажмите `EXR-папка`.
2. Для EXR-секвенции приложение соберёт непрерывную нумерацию в этой папке,
   проверит пропуски и назначит 24 fps.
3. Нажмите `Выбрать трек` и укажите shot, `3d_track`, `camera` или конкретную
   папку версии `vNNN`.
4. Приложение найдёт `3d_track\camera\vNNN`, выберет последнюю версию и
   прочитает `*_distort_vNNN.nk`.
5. Выберите фактический входной colorspace plate. Список берётся из OCIO
   установленного Nuke; по умолчанию используется `ACES2065-1`.
6. Проверьте длительность, рассчитанный холст и оба preview.
7. Добавьте shot в очередь и нажмите `Старт`.

Оба preview используют один выбранный input colorspace и один ACES Display/View
Transform в Rec.709. Цвет между исходной и undistort-версией не меняется;
отличается только геометрия и включённая обработка.

Исходный plate и `.nk` открываются только для чтения.

## 4K И Разрешение

Режим по умолчанию: `Нормализовать в 1920×1080`, как в предоставленном
эталонном Nuke-скрипте. Режим `Сохранить исходное` доступен вручную.

- UHD/4K сначала **не** уменьшается до 1920×1080.
- Undistort сохраняет исходный пиксельный масштаб и геометрию.
- Если полезная область выходит за границы, приложение расширяет чёрный холст
  до ближайшего точного 16:9.
- Auto zoom и crop не применяются.

Ручной режим `Нормализовать в 1920×1080` повторяет порядок эталонного
Nuke-скрипта: denoise, BlackOutside и undistort выполняются в исходном
разрешении, после чего применяется финальный Reformat в HD. Выбор сохраняется.

## Длительность

Автоматический режим:

- округляет длину вверх до целых секунд;
- минимум 4 секунды;
- максимум 15 секунд;
- короткий plate дополняет последним кадром;
- длинный plate обрезает.

Можно вручную указать целое значение от 4 до 15 секунд.

## Результаты

Для `SHOT` создаются:

```text
SHOT_conform.mov
SHOT_conform_tv.mp4
SHOT_conform_qc.json
```

Основной файл:

- Apple ProRes 4444 (`ap4h`);
- 12-bit 4:4:4:4 decode format;
- Rec.709;
- исходный/project fps;
- без звука.

Topview:

- H.264 High;
- Rec.709;
- тот же fps, хронометраж и холст;
- без crop;
- двухпроходный bitrate с запасом под лимит 64 МБ.

QC JSON содержит пути исходника и трека, версию track, colorspace, fps,
длительность, canvas, фактические codec/dimensions/size готовых файлов и
тайминги decode/denoise/remap/reformat/OCIO/encode.

MOV, Topview и QC сначала пишутся во временные `.part`-файлы. Полный комплект
публикуется только после проверки обоих видео; при ошибке или остановке все
частичные результаты удаляются. Существующие файлы не перезаписываются:
добавляется `_1`, `_2` и так далее.

## Производительность

EXR-секвенции читаются напрямую через OpenEXR/OpenCV без промежуточного 4K
FFmpeg pipe. 3DE remap выполняется нативным OpenCV, OCIO параллелится по полосам
кадра, а чтение следующего EXR совмещается с обработкой текущего. NumPy остаётся
fallback. Статическая lens map рассчитывается один раз на shot; анимированная —
для каждого кадра. ProRes 4444 и двухпроходный Topview кодируются на CPU,
поскольку NVENC не кодирует ProRes и не даёт нужный двухпроходный
size-controlled тракт.

## Очередь

- `Старт` запускает ожидающие задания.
- `Пауза` заканчивает текущий shot и не начинает следующий.
- `Стоп` запрашивает штатную остановку текущего backend, дожидается её и при
  необходимости завершает всё дерево FFmpeg принудительно.
- `Очистить` сначала останавливает активный backend, затем очищает очередь.
- `Повторить` ставит копию задания с теми же зафиксированными параметрами.

Для каждого shot видны preview, процент, этап обработки, параметры и готовый
MOV. Закрытие или сворачивание окна прячет приложение в tray.

## Настройки

Настройки автоматически сохраняются здесь:

```text
%LOCALAPPDATA%\GFX Ai Conv\settings.json
```

Постоянные журналы приложения и отдельных worker:

```text
%LOCALAPPDATA%\GFX Ai Conv\logs
```

Приложение записывает:

- запуск, закрытие и состояние renderer;
- действия с элементами интерфейса и изменения настроек;
- входные и выходные параметры IPC;
- найденные версии Nuke, OCIO и пути runtime;
- запуск backend, все этапы и проценты обработки;
- полный stdout/stderr каждого worker;
- ошибки JavaScript, Python и FFmpeg со stack trace.

Кнопка `Собрать логи` создаёт ZIP в выбранном месте. В архив входят журналы,
снимок очереди, настройки и сведения о системе. Plate, видео, EXR и `.nk`
никогда не копируются. `app.log` ротируется при достижении 10 МБ, сохраняются
восемь предыдущих файлов.

Сохраняются:

- режим output: автоматический `shot\ai\conform` или ручная папка;
- последний ручной output;
- input colorspace;
- автоматическая/ручная длительность;
- политика разрешения;
- сила temporal denoise;
- последние папки plate и track.

## Обновления

Приложение проверяет последний GitHub Release при старте и по кнопке
`Обновления`. Скачивание, прогресс и запуск тихого installer происходят в
одном окне. Перед установкой проверяются репозиторий, версия, точный размер и
SHA-256 файла из GitHub Release. Повреждённый или подменённый файл не
запускается. Сеть должна разрешать:

Запросы выполняются через Chromium и учитывают системные настройки прокси
Windows. Сторонние зеркала для установщика не используются.

```text
https://api.github.com
https://github.com
```


## Сборка Windows

```powershell
npm.cmd run dist
```

Результат появляется в `dist/`:

- NSIS installer `.exe`;
- unpacked `.zip`.

`package.json` включает в installer:

- Electron renderer/main;
- `backend/*.py`;
- `vendor/py311` с NumPy;
- `ffmpeg-static`;
- third-party notices.

## GitHub Release

Workflow `.github/workflows/release.yml` запускается по version tag и собирает
Windows installer/zip:

```powershell
git tag v0.2.0-alpha.6
git push origin feature/ai-conform
git push origin v0.2.0-alpha.6
```

Перед публичным alpha-release изменения следует слить в `main`, после чего
создать tag на merge commit.
